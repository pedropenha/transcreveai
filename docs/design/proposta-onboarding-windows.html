Proposta de design · Onboarding · Windows

Instalou, já está pronto

No Windows o usuário não escolhe modelo nem configura provedor. O Parakeet V3 é baixado sozinho, o atalho já vem definido e, se o Claude Code ou o Codex estiver instalado, ele passa a gerar os resumos das reuniões. Se nenhum dos dois estiver instalado, o app avisa e deixa instalar agora ou mais tarde. No macOS nada muda.

Instalador→ Microfone (já existe, pula sozinho se liberado)→ Preparando o Transcreve.ai (novo, substitui a lista de modelos)→ Hub
Mudança de comportamento por trás da tela: hoje o provedor dos resumos vem como openai, e sem chave de API o resumo falha. Na proposta, quando o Claude Code ou o Codex é detectado no primeiro uso, ele vira o provedor dos resumos (e do assistente) automaticamente. Ninguém precisa abrir as Configurações.

1 · Tela “Preparando”, caminho feliz

Usa o mesmo padrão de cartões da tela de permissões (ícone redondo, título, descrição, estado). Cada linha passa de “em andamento” para “pronto”. O botão Começar só libera quando o modelo termina de baixar.

2 · Nenhum agente encontrado

O modelo continua baixando normalmente. Só a linha das reuniões muda para o tom de aviso e explica por que importa. O app não instala nada por conta própria: ele abre a instrução oficial e confere de novo.

3 · Quem deixou para depois

Um aviso discreto no topo do Notetaker, no mesmo tom de warning, que some quando um agente é detectado ou quando o usuário fecha. As reuniões já gravadas continuam com o chip “Sem resumo” que existe hoje.

4 · Baixar o modelo no instalador?

Você pediu que o download aconteça na instalação. Dá para fazer, porque o instalador já baixa o WebView2 do mesmo jeito. Mas tem custos. Abaixo, as três opções:

Opção Prós Contras
A. Instalador baixa Abre o app e já está tudo pronto. Instalação mais lenta. Sem internet, a etapa falha. O NSIS não confere o hash do arquivo. É mais script NSIS para manter.
B. Modelo dentro do instalador Funciona offline. Instalador fica com mais de 750 MB, e cada atualização baixaria tudo de novo.
C. App baixa no 1º uso (tela 1a) ✓ Usa o download que já existe, com conferência de hash, retomada e cancelamento. Funciona igual em qualquer instalação. O usuário vê o progresso. Na primeira abertura, espera o download terminar (a tela mostra o progresso).

Recomendo a C, com a opção de juntar com a A: se o instalador já baixou o arquivo, a tela 1a abre direto com “✓ Instalado”.

Escopo técnico, em resumo

  • Windows, primeira execução: a lista de modelos dá lugar à tela “Preparando”, que baixa e seleciona o Parakeet V3 (o GGUF que hoje já aparece em destaque no pt-BR).
  • Detecção do agente pelo comando cli_agents_status, que já existe. Ao detectar, o provedor de pós-processamento/resumo passa a ser cli_agent/claude ou cli_agent/codex, sem sobrescrever uma escolha que o usuário já tenha feito.
  • Textos novos em en e pt-BR. A spec F010/F009 é atualizada no mesmo PR.
  • macOS e Linux continuam com o fluxo de hoje.
