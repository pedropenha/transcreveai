# Audio fixtures

pt-BR WAV fixtures (16 kHz, mono, PCM16) shared by the E2E tests (T-009), the
text-pipeline tests (T-035) and future WER/latency benchmarks (T-017).

| File                           | Duration | Content                                                                                                                                             |
| ------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pt-br/fala_curta.wav`         | ~1.7 s   | Short utterance — two two-syllable "words" (stands in for "olá mundo")                                                                              |
| `pt-br/fala_longa_muletas.wav` | ~19.9 s  | Long utterance with hesitation drones ("ahn/ééé"-like), long thinking pauses, and immediate word repetitions — the muletas case for `light` cleanup |

> **These are synthetic, speech-_like_ signals** generated by
> [`generate.py`](generate.py) (pure stdlib, fixed seeds → byte-identical
> regeneration). They exercise capture timing, VAD gating and the pipeline, but
> are not intelligible speech, so no `expected.txt` transcript exists yet. When
> real recorded pt-BR speech becomes available, drop it in under the same
> filenames and add an `expected.txt` per file.

Regenerate:

```bash
python e2e/fixtures/generate.py
```

Use in a test build (PowerShell):

```powershell
cargo build --features audio-fixture   # feature lives only in test builds
$env:TRANSCREVE_AUDIO_FIXTURE = "$PWD\e2e\fixtures\pt-br\fala_curta.wav"
.\<target>\debug\transcreve-ai.exe
```

Each dictation session replays the file from the top; between sessions the
feeder emits silence. See [`../README.md`](../README.md) and
[`../native/README.md`](../native/README.md).
